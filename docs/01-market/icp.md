# ICP — Ideal Customer Profile

## 이 문서로 내릴 결정

1. **누구한테 첫 1,000개 워크스페이스를 팔 것인가**
2. 영업이 **"이 리드는 쫓고 / 이 리드는 패스"**를 결정하는 기준
3. 제품 결정에서 **"이건 ICP가 원하는 것이냐"**를 판단

> 원칙: ICP가 명확하지 않으면 가격도 채널도 메시지도 다 흐려진다. **광범위한 ICP = ICP 없음**.

---

## 단계별 ICP 정의

우리는 SMB로 진입해서 미드마켓으로 확장한다. ICP는 단계마다 다르다.

| 단계               | 타깃 규모           | 시점                  | 우선순위 |
| ------------------ | ------------------- | --------------------- | -------- |
| ICP-1 (Beachhead)  | 30-80명 IT 회사     | Phase 1-2 (2026-2027) | 1순위    |
| ICP-2 (Expansion)  | 80-200명 SMB        | Phase 2-3 (2027-2028) | 2순위    |
| ICP-3 (Mid-market) | 200-2000명 미드마켓 | Phase 3-4 (2028-2029) | 3순위    |

각 단계에서 **앞 단계 ICP가 자라서** 다음 단계로 가도록 설계되어야 한다 (확장 비용 0 원칙).

## ICP-1: 한국 30-80명 IT 회사 (Beachhead)

### 회사 프로파일

| 차원           | 기준                                                                  |
| -------------- | --------------------------------------------------------------------- |
| 규모           | 정규직 30-80명                                                        |
| 산업           | 소프트웨어 / SaaS / 게임 / 핀테크 / 이커머스 (IT 중심)                |
| 위치           | 한국 본사 (서울/판교 위주)                                            |
| 성장 단계      | 시리즈 A 후반 ~ 시리즈 B 초반 (연 매출 30억 ~ 200억 KRW)              |
| 성장 속도      | 직전 12개월 인원 증가 30%+                                            |
| 현재 도구 스택 | Slack 또는 카카오워크 + Jira/Linear/Notion + 별도 HR (Flex 또는 엑셀) |
| 의사결정 시간  | 30일 이내                                                             |
| 결제 방식      | 카드 결제 또는 세금계산서                                             |

### 왜 이 프로파일인가

1. **30명 미만**: 도구가 필요하다는 인식이 약함. Slack + 엑셀로 충분하다고 믿음. 마케팅 비용 대비 LTV 낮음.
2. **80명 초과**: 이미 Jira / Workday를 도입했고 마이그레이션 비용이 큼. 우리가 Phase 1 제품으로 못 이김.
3. **IT 회사**: 우리 PM 도메인의 워크플로우(스프린트, 보드, 이슈)가 그들의 일상과 일치. 비IT는 학습 비용 큼.
4. **한국 본사**: 우리 KR-first 컴플라이언스가 1차 가치. 글로벌 본사 자회사는 본사 도구 강제로 우리가 못 들어감.

### 페르소나 (의사결정자 + 사용자 + 챔피언)

#### 챔피언: COO / Head of Ops (정수영, 36세)

**역할**: 30-80명 회사의 운영 전반 책임. CEO 직속.

**일상의 고통**

- Slack에서 본 결정이 Jira 티켓에 안 옮겨져 다음주에 다시 논의
- HR 이슈 (입사, 퇴사, 평가) 처리에 본인이 매번 노무사와 카톡 왕복
- 신입 입사 시 Slack/Jira/Notion/Flex 4개 계정 만들기, 권한 설정에 1시간
- CEO에게 "지금 회사 가장 큰 블로커가 뭐냐"를 답하지 못함 — 데이터가 흩어져있어서

**그가 1년에 해결하고 싶은 것**

- 회사 운영 가시성 확보 (CEO 보고용)
- HR 행정 시간 50% 감소
- 도구 SaaS 비용 합리화 (현재 직원당 월 7-12만원 누적)

**구매 의사결정 권한**: 도구 도입 결정 (CEO 승인 필요 단계는 월 300만원 이상)

**우리가 이 사람을 어떻게 잡는가**: "회사 운영 한 화면" 데모. 30분 안에 PM + Comms + HR 통합 가치 보여주기.

#### 의사결정자: CEO / 대표 (김민서, 41세)

**일상의 고통**

- "이번달 매출/비용/인원이 어떻게 변했는지" 답하려면 3-4개 도구를 본인이 들여다봐야 함
- 직원이 늘면서 회사가 무엇을 하고 있는지 감각이 사라짐
- 투자사 보고 자료 매번 사람이 손으로 만듦

**구매 의사결정 권한**: 최종 승인. ACV 1,000만원 초과 시 본인이 결정.

**우리가 이 사람을 잡는 메시지**: ROI. "현재 SaaS 비용 X에서 Y로 절감 + 운영 가시성 확보"

#### 사용자: 엔지니어 / 디자이너 / 운영팀 (다수)

**핵심 인사이트**: 이 사람들은 챔피언이 도입을 결정해도, 본인이 안 쓰면 도입이 실패한다. 우리는 사용자 NPS를 챔피언 NPS만큼 챙겨야 한다.

**이들의 기준**

- "Linear/Slack 수준으로 빠르냐"
- 키보드 단축키, 검색 속도
- 본인 도메인(PM)에서 잘 동작하는지

**우리가 이 사람들을 잡는 메시지**: "당신이 좋아하는 Linear UX + 회사 전체 데이터"

#### 차단자 (Blocker): IT/보안 담당자

**일상의 고통**: 새 SaaS 도입할 때마다 보안 검토. SSO 안 되면 거부.

**우리가 이 사람을 안 차이게 하는 방법**

- Phase 1에서도 SSO (Google/Microsoft) 지원
- 보안 백서 (Whitepaper) Phase 1에 준비
- SOC2 로드맵 공개

## ICP-1 자격 기준 (BANT + 한국식)

영업이 30분 콜에서 묻고 답을 받아야 할 기준.

| 차원            | Qualify                                            | Disqualify              |
| --------------- | -------------------------------------------------- | ----------------------- |
| Budget          | 직원당 월 1.5만원 이상 SaaS 지불 의향              | "무료가 아니면 안 씀"   |
| Authority       | COO / Head of Ops / CEO와 30일 내 미팅 가능        | 인사담당자 1명만 연결됨 |
| Need            | 도구 3개 이상 중복 사용 + Slack에서 정보 누락 경험 | "지금 Notion으로 다 됨" |
| Timeline        | 다음 분기 내 도입 의사                             | "내년에 다시 봅시다"    |
| 추가: 성장      | 직전 12개월 30%+ 인원 증가 또는 시리즈 A 펀딩 완료 | 인원 감소 중            |
| 추가: 한국 본사 | KR 법인이 의사결정 주체                            | 글로벌 본사 도구 강제   |

이 6개 중 4개 미충족이면 ICP-1 외. 사이클에 넣지 말 것.

## ICP-2: 한국 80-200명 SMB (Expansion)

이 단계에서는 새 고객을 잡는 동시에 **ICP-1 워크스페이스가 자라서 들어옴**. 두 경로가 다르다.

### 자생 경로 (Expansion from ICP-1)

ICP-1 워크스페이스 중 50%가 18개월 안에 80명을 넘는다고 가정한다 (시리즈 B 진입). 이들이 자연 확장하면 ACV가 2-3배로 자란다.

이 경로의 성공 조건:

- 시트 80개 넘어가도 성능 저하 없음
- HR 도메인이 80명 시점에 신뢰할 만큼 성숙 (Phase 3 종료까지)

### 신규 획득 경로

이 단계 신규 고객은 이미 Jira + Slack + Flex를 쓰고 있다. 마이그레이션 동기가 필요하다.

| 트리거                              | 우리가 잡는 메시지                                                    |
| ----------------------------------- | --------------------------------------------------------------------- |
| Atlassian 가격 인상 / 라이선스 갱신 | "라이선스 4개 + Flex = 직원당 월 25만원. Conflow는 12만원에 더 많이." |
| Slack Enterprise Grid 견적 받음     | "Enterprise Grid 가기 전에 Conflow로 갈아타면 HR/문서까지 포함"       |
| 미드마켓 진입 준비 (SOC2 요구받음)  | "이미 SOC2 Type II 보유, 같이 가져가세요"                             |
| AI 도입 압박 (CEO가 ChatGPT 봤음)   | "도메인 횡단 AI는 우리만"                                             |

## ICP-3: 미드마켓 200-2000명 (Phase 3+)

### 회사 프로파일

- 정규직 200-2000명
- 시리즈 C 이상 또는 IPO 준비
- IT/보안팀 별도 존재
- SOC2 / ISO27001 / K-ISMS 요구

### 자격 기준

| 차원 | Qualify                                                |
| ---- | ------------------------------------------------------ |
| 보안 | SSO/SCIM 필수, 감사로그 보유 의무, DLP 정책 보유       |
| 결제 | 연 단위 계약, 청구서 결제, 부가세 처리                 |
| 도입 | 6개월 PoC 가능, 보안 검토 통과 필요                    |
| 추가 | HR 도메인이 외주 (Workday/Flex) 아닌 Conflow 사용 의향 |

이 단계는 영업 주도(SLG) 비중이 PLG와 50:50이다. SDR + AE 팀 필요.

## 명백한 비-ICP (시간 낭비 방지)

다음은 좋아 보여도 우리 ICP가 아니다. 거절 또는 셀프서비스로 우회.

1. **5-15명 초소형 스타트업**: Notion으로 충분. 우리는 학습 비용 회수 못 함.
2. **비IT SMB (제조업, 유통, 식음료)**: PM 도메인 워크플로우가 안 맞음. 학습 비용 너무 큼.
3. **공공기관 / 대학**: 조달 사이클 18개월. 우리는 PLG 회사다.
4. **금융 (은행/증권)**: 망 분리, 클라우드 정책. 우리 아키텍처와 안 맞음.
5. **글로벌 본사 자회사**: 도구 결정권이 본사. 우리가 진입 못 함.
6. **노조 강한 대기업 자회사**: HR 도메인 정치 복잡. 미드마켓 단계에서 별도 전략 필요.

## ICP 가설 검증 계획

이 ICP는 **가설**이다. Phase 0-1 진입 전 검증한다.

### 검증 1: 정성 인터뷰 (Phase 0)

- 대상: 30-80명 한국 IT 회사 COO/Head of Ops 5명
- 질문 가이드: `01-market/jtbd.md` 참고
- 통과 기준: 5명 중 4명이 "이 문제 있다, 30일 안에 도구 검토하겠다"

### 검증 2: 랜딩 페이지 컨버전 (Phase 1 초)

- "30-80명 한국 IT 회사" 타깃 광고 → 베타 신청
- 통과 기준: 광고 CPL 5만원 이하, 신청 → MQL 전환 30%+

### 검증 3: 베타 유료 전환 (Phase 1 말)

- 베타 워크스페이스 100개 중 유료 전환 20%+
- 미달 시 ICP 재정의

## ICP 변경 정책

ICP는 분기마다 데이터로 재검토한다. 변경 트리거:

- 신규 고객의 ACV/CAC 비율 < 2 → 가설 점검
- 30-80명 구간 신규 워크스페이스 비율 < 60% → 진입 메시지 점검
- 비IT 산업 워크스페이스가 자연 발생 30%+ → ICP 확장 검토

변경 결정은 **분기 GTM 리뷰**에서. 즉흥적 ICP 확장은 금지.
