# Phase별 KR 측정 정의 + 분기 GTM 리뷰 대시보드

이 문서는 [`phases.md`](./phases.md)의 14개 분기 OKR과 [`product-vision.md`](../00-vision/product-vision.md)의 5년 North Star · Watch List 6개를 **"무엇을 보고 어떻게 판단하는가"**의 측정 정의로 풀어낸 데이터 문서다. [`moscow.md`](./moscow.md)의 재분류 트리거 임계치와 [`domain-overview.md`](../02-product/domain-overview.md)의 이벤트 카탈로그 13개·A2UI Tool 16개를 1차 데이터 소스로 받는다.

> 이 문서는 **데이터의 약속**이다. 분기 OKR이 "방향 + 임계치"이고 MoSCoW가 "Must/Should/Could/Won't의 분류"라면, 이 문서는 **"그 임계치를 어떤 테이블/이벤트의 어떤 계산으로 확인하는가"**다. KR을 적기는 쉽지만 측정 정의를 안 박으면 분기 리뷰에서 "달성 여부 판단 불가" 상태가 된다.

> **draft v1 가설 주의**: 모든 임계치·계산식·데이터 소스는 v1 가설이다. 데이터 인프라(Metabase/Superset/Looker 선택, 이벤트 수집 파이프라인 SQL) 결정은 [`04-architecture/tech-stack.md`](../04-architecture/) (TODO)에 위임. 이 문서는 **무엇을 측정할 것인가의 계약**이지 어떻게 구현할 것인가의 구현서가 아니다.

## 이 문서로 내릴 결정

1. **각 분기 KR의 데이터 소스·계산식·임계치·책임자를 박는다** — 분기 GTM 리뷰에서 "이 KR이 달성된 건가?" 질문에 1-2분 안에 답할 수 있어야 한다.
2. **Phase 진입·종료 게이트의 측정 게이트를 박는다** — 어느 메트릭이 임계치를 넘어야 다음 Phase에 진입하는가, 미달 시 어떤 액션이 발동되는가.
3. **Watch List 6개의 사전 신호 메트릭을 박는다** — Watch List가 "발동된 후"가 아니라 "발동 전 60-90일에 보이는 신호"가 무엇인가. 사전 신호 미정의 = 리액티브 운영.
4. **분기 GTM 리뷰 대시보드 4종의 구성을 박는다** — 매 분기 어떤 화면 4개를 띄울 것인가. 백 개 메트릭 중 어떤 20개를 1차 점검 대상으로 두는가.
5. **PLG → SLG 전환 측정 체계를 박는다** — PQL/SQL 정의, ICP-2/3 자생 확장률, 영업 사이클의 측정 단위. Phase 3 진입 결정의 데이터 근거.
6. **Vanity vs Action 메트릭의 경계를 박는다** — 가입자 수·MAU·메시지 수가 아니라 무엇을 보는가. "안 보면 안 깨지는 메트릭"을 명시.

## 측정 원칙 (Measurement Principles)

각 KR을 적기 전에 박는 5가지 메타 규칙. 이 규칙을 어기는 KR은 측정 정의서에서 제외하고 분기 리뷰에서 재정의.

### 원칙 1. 모든 KR은 데이터 소스가 명시되어야 한다

KR을 정의할 때 **"어느 테이블의 어느 컬럼 / 어느 이벤트의 어느 페이로드 필드"**를 박지 않으면 KR이 아니라 슬로건이다. 예: "유료 워크스페이스 100개"는 KR이 아니다 — "`workspace` 테이블에서 `tier IN ('team', 'business', 'enterprise')` AND `subscription.status='active'` 카운트"가 KR이다.

- 데이터 소스 후보 카탈로그: [`domain-overview.md`](../02-product/domain-overview.md) Shared Core 5개 + 4도메인 엔티티 + 이벤트 카탈로그 13개 + AuditLog
- KR이 외부 데이터(인터뷰 / NPS 설문 / PoC 정성 평가)에 의존하면 **수집 방식**(인터뷰 가이드, NPS 도구, PoC 평가 매트릭스)을 명시

### 원칙 2. North Star → Phase 게이트 → 분기 KR로 트리클다운

지표는 3계층으로 정렬한다. **상위 → 하위로 내려가야** 측정 부담이 분산된다.

| 계층            | 정의                                                | 주기      | 책임자                   | 갱신 트리거                   |
| --------------- | --------------------------------------------------- | --------- | ------------------------ | ----------------------------- |
| **North Star**  | 2031년 한국 IT SMB 유료 워크스페이스 점유율 12-18% | 연간      | CEO + Product Lead       | 연 1회 + Watch List 신호      |
| **Phase 게이트** | 각 Phase 종료 조건 (정량 + 정성)                    | Phase 종료 | Product Lead             | Phase 종료 분기               |
| **분기 KR**     | phases.md의 분기별 3-5개 KR                         | 주간/월간 | 각 KR 책임자             | 분기 시작 + 매주 핫리스트     |
| (보조 지표)     | Vanity 메트릭 (가입자, MAU)                         | 일간      | (참고용, 의사결정 입력 X) | -                             |

원칙: 분기 KR이 달성되지 않아도 Phase 게이트가 충족될 수 있다. 그러나 **Phase 게이트가 미충족이면 다음 Phase 진입 자동 보류**.

### 원칙 3. Watch List 사전 신호는 게이트 이전에 발견되어야 한다

[`product-vision.md`](../00-vision/product-vision.md) Watch List 6개는 **Phase 종료 시점에 발견**되도록 정의되어 있다. 그런데 그 시점이면 이미 늦다. 각 Watch List마다 **60-90일 전에 보이는 사전 신호 메트릭**을 1-2개 박는다.

- 사전 신호 관찰 주기: 월간 또는 격주
- 사전 신호 임계치 3단계: **관찰** (정상) → **경계** (분기 리뷰 1차 점검) → **발동** (Watch List 본 신호 트리거)
- 사전 신호 발견 시 액션: 분기 기다리지 않고 비상 리뷰

### 원칙 4. Vanity vs Action 메트릭 구분

**Vanity 메트릭**: 보면 기분 좋지만 의사결정 입력이 아닌 것. 예: 가입자 수, MAU, 메시지 수.
**Action 메트릭**: 보고 무엇을 할지 결정되는 것. 예: 유료 전환율, ICP-2 자생 확장률, A2UI PoC 통과율.

| 영역       | Vanity (참고만)              | Action (의사결정 입력)                                              |
| ---------- | ---------------------------- | ------------------------------------------------------------------- |
| 가입       | 신규 워크스페이스 가입 수    | Free → Team 전환율 (가입 후 14일 / 30일 / 90일)                     |
| 사용       | MAU, DAU, 메시지 수          | 주 3회+ 활성 워크스페이스 비율, ICP-1 워크스페이스의 Must 기능 사용률 |
| AI         | A2UI Tool 호출 수             | A2UI 도메인 횡단 Tool의 결과 채택률, Decision 추출 정밀도            |
| 가격/매출  | 누적 ARR, 누적 워크스페이스 수 | NRR(Net Revenue Retention), 이탈률, ACV 중앙값                       |
| 영업       | 견적 발송 수                  | 견적 → 클로징 전환율, 영업 사이클 중앙값, ACV 중앙값                  |

**규칙**: 분기 GTM 리뷰 대시보드 4종의 80%는 Action 메트릭. Vanity는 "성장 추세 참고"용으로만 1개 패널.

### 원칙 5. 한국 컨텍스트 메트릭 (한국 IT SMB 모집단 정의)

North Star의 분모인 "한국 IT SMB 8,000-12,000개사"의 정의를 박는다. 이 분모가 흐려지면 점유율 지표 자체가 흐려진다.

- **분모 (한국 IT SMB)**: 한국에 본사를 두고 [`icp.md`](../01-market/icp.md) ICP-1·ICP-2 자격 기준에 부합하는 IT 회사 (30-200명, 직원당 월 1.5만원+ SaaS 지불 의향, 한국 IT 산업코드). 출처: 스타트업얼라이언스 + 중기부 + 자체 외삽
- **분자 (Conflow 유료 워크스페이스)**: `workspace.tier IN ('team', 'business', 'enterprise')` AND `subscription.status='active'` AND `workspace.region='kr'`
- **갱신 주기**: 분모는 연 1회 (외부 데이터 갱신), 분자는 월간
- **편차 허용**: ±15% (외삽 정확도 한계)

> 한국 미드마켓(200-2000명, ICP-3)은 분모 800-1,200개사 추정. North Star의 보조 지표 ("미드마켓 신규 도입 회사 중 30%+가 Conflow를 비교 대상에 포함")의 분모.

## North Star Metric

> **2031년, 한국 IT SMB 유료 워크스페이스 점유율 12-18% (≈ 1,500개 워크스페이스, ACV 평균 4,000만원)** — [`product-vision.md`](../00-vision/product-vision.md) 5년 후 모습.

### 계산식

```
North Star = (Conflow 한국 유료 워크스페이스 수) / (한국 IT SMB 모집단 수)

여기서:
  분자 = COUNT(workspace WHERE
              tier IN ('team', 'business', 'enterprise')
              AND subscription.status = 'active'
              AND region = 'kr'
              AND employee_count BETWEEN 30 AND 200)
  분모 = (한국 IT SMB 30-200명 모집단, 2026 추정 8,000-12,000개사)
```

### 측정 정의

| 항목           | 내용                                                                                              |
| -------------- | ------------------------------------------------------------------------------------------------- |
| 측정 주기      | 분자 월간 / 분모 연 1회                                                                            |
| 데이터 소스    | 분자: `workspace`, `subscription` 테이블 / 분모: 스타트업얼라이언스 + 중기부 외부 데이터          |
| 임계치 (2031) | 12-18% (≈ 960-2,160개 워크스페이스, 중심값 1,500개)                                               |
| 보조 지표 1   | 미드마켓 (200-2000명) 신규 도입 회사 중 비교 대상 포함률 30%+ — 분기 1회 시장 조사 (15-30개사 설문) |
| 보조 지표 2   | ARR (분자 × 평균 ACV) — 2031년 약 600억원 (1,500 × 4,000만원)                                       |

## 측정 안티패턴 (잘못 측정하면 무엇이 깨지나)

분기 GTM 리뷰에서 다음 6가지를 메트릭으로 들고오면 의사결정이 흐려진다. 명시적으로 금지.

### 1. Vanity 사용자 수 (가입자 / MAU / 메시지 수)

**왜 금지**: ICP-1 검증과 무관. ICP-1 자격 (30-80명 한국 IT 회사) 외의 가입자는 PMF 신호가 아니다. 의사결정 입력으로 쓰지 말 것.

**대체 메트릭**: ICP-1 자격 워크스페이스의 주 3회+ 활성률 / Must 기능 사용률.

### 2. Free 가입 수만 보고 전환 미관찰

**왜 금지**: Free 가입자가 많아도 Phase 1 종료 조건 (유료 100개) 미달 가능. Free → Team 전환율을 함께 보지 않으면 PLG 깔때기 결함이 늦게 발견된다.

**대체 메트릭**: 14일 / 30일 / 90일 코호트 전환율 + PQL 비율.

### 3. 미드마켓 1건 deal로 ACV 평균 왜곡

**왜 금지**: Phase 3-4 미드마켓 1-2개 워크스페이스가 ACV 1억원+ 클로징하면 평균이 사실보다 좋아 보인다. 의사결정 (영업 사이클 / Enterprise floor) 왜곡.

**대체 메트릭**: 평균 ACV + **중앙값(median) ACV 병행 표시**. 분기 GTM 리뷰 대시보드 3에 양쪽 패널.

### 4. Decision 추출 confidence 평균 ≠ 정확도

**왜 금지**: AI Tool의 confidence 점수 평균이 0.85여도 실제 정확도는 70%일 수 있다 (calibration 결함). 정확도 측정은 **골든 셋 + 사용자 검증**으로만.

**대체 메트릭**: Decision 추출 정확도 = COUNT(decision WHERE user_confirmed=true) / COUNT(decision WHERE confidence >= 0.7) — 골든 셋 + 사용자 confirm 로그.

### 5. 노무사 외부 협업 "초대 수" ≠ "활성 사용률"

**왜 금지**: 초대 보내고 노무사가 1회 로그인하고 안 쓰면 차별화 축 3 무력화. 초대 수로 측정하면 Phase 3 종료 조건 (30%+) 충족 같지만 실제로는 미달.

**대체 메트릭**: 노무사 외부 협업 **사용률** = COUNT(workspace WHERE external_nomu_advisor 활성 사용 in last 60 days) / COUNT(workspace WHERE hr_module_active). 60일 활성 정의: 검토 큐 진입 1회+ AND 코멘트 또는 승인 1회+.

### 6. 분기 NPS 1회만 보고 추세 미관찰

**왜 금지**: NPS 분기 1회 측정은 노이즈가 크다. 한 분기 NPS 35 → 다음 분기 28 → 그 다음 32일 때 25-35 범위 노이즈인지 추세 하락인지 판단 불가.

**대체 메트릭**: NPS 4분기 이동 평균 + 응답률 + 자유 답변 키워드 분석. Promoter/Detractor 자유 답변에서 ["속도 느림", "임포터 오류", "노무사 권한"] 키워드 빈도 추세.

## 변경 정책

이 문서는 **3개 트리거** 시 갱신한다.

1. **분기 GTM 리뷰**: 위 "대시보드 4종"의 4개 화면이 분기마다 가동되어야 한다. 메트릭 정의가 실제 분기 리뷰에서 사용 불가능하면 (예: 데이터 소스 미정의, 임계치 모호) 갱신. 이 문서의 측정 정의는 분기 GTM 리뷰의 **운영 문서**여야 한다.
2. **Phase 종료**: 각 Phase 종료 시점에 다음 Phase의 분기 KR 측정 정의 / 진입 게이트 / Watch List 사전 신호 임계치 재정의. Phase 종료 조건 미충족 시 Watch List 발동 점검 즉시.
3. **Watch List 신호 발견**: [`product-vision.md`](../00-vision/product-vision.md) Watch List 6개 또는 [`domain-overview.md`](../02-product/domain-overview.md) Watch List 신호 1개+ 발견 시 분기 기다리지 않음. 사전 신호 임계치 조정 가능.

**금지 사항**

- KR 측정 정의 없이 분기 OKR 박기 — 거절. 이 문서에 정의 안 된 KR은 분기 GTM 리뷰에서 "달성 여부 판단 불가"로 처리.
- Vanity 메트릭을 의사결정 입력으로 쓰기 — 위 "측정 안티패턴" 6개 위반 시 분기 리뷰에서 제외.
- 데이터 인프라 결정 (Metabase 등) 이 문서에서 박기 — 위임처로 자동 이전.
- 사전 신호 발견 시 분기 리뷰 대기 — 비상 리뷰로 즉시 전환.

**책임자**: Product Lead (1차) + Data Engineer (분기 KR 측정 가능성 검증) + Sales Lead (PLG → SLG 측정의 영업 측 검증). 갱신 시 변경 이력을 본 파일 하단에 추가.
