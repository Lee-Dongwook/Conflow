# Phase별 출시 일정 + 분기 OKR

이 문서는 [`product-vision.md`](../00-vision/product-vision.md)의 **Phase 0→4 모델**과 [`moscow.md`](./moscow.md)의 **Must/Should/Could/Won't** 분류를 **분기 단위 OKR**로 재정렬한 실행 문서다. 도메인 문서 4개([`domain-pm.md`](../02-product/domain-pm.md) / [`domain-comms.md`](../02-product/domain-comms.md) / [`domain-hr.md`](../02-product/domain-hr.md) / [`domain-documents.md`](../02-product/domain-documents.md))의 "Phase별 출시" 표가 1차 입력이다.

> 이 문서는 **무엇을 언제 만들 것인가의 시간축**이다. 무엇이 Must인가는 [`moscow.md`](./moscow.md), 왜 그 Phase인가는 [`product-vision.md`](../00-vision/product-vision.md), 무엇을 측정해 성공/실패를 판단하는가는 [`metrics.md`](./metrics.md) (TODO).

> **draft v1 가설 주의**: 분기 OKR의 Key Results 숫자는 v1 가설이다. 각 Phase 종료 시점에 다음 Phase의 OKR을 데이터 기반으로 재정의한다. 분기 OKR을 절대 숫자로 박지 말고 "방향 + 임계치"로 읽을 것.

---

## 이 문서로 내릴 결정

1. **각 Phase의 진입·종료 분기를 박는다** — 2026 Q3 ~ 2029 Q4+ 14개 분기를 5 Phase로 매핑. 일정이 흔들릴 때 어느 항목을 자르는지의 1차 근거.
2. **분기별 Objective와 Key Results를 박는다** — 한 분기 한 Objective 원칙. KR은 3-5개. 분기 시작 시 영업/엔지니어링/디자인이 한 화면에서 합의할 수 있는 단위.
3. **Phase 간 마이그레이션 결정 시점을 박는다** — 예: Phase 2→3 Event Bus (PostgreSQL outbox → Kafka) 전환 트리거, Phase 3→4 KISA 자체구축 vs 모두싸인 OEM 결정 시점, PLG → SLG 50:50 진입 분기.
4. **Phase 종료 조건의 정량/정성 임계치를 박는다** — 미충족 시 다음 Phase 진입을 6-12개월 지연시키는 액션 규칙.
5. **분기별 리스크 핫리스트를 정의한다** — 분기 GTM 리뷰의 1차 점검 대상.
6. **04-architecture/로 위임하는 항목과 metrics.md로 위임하는 항목을 명시한다** — 이 문서가 다루지 않는 것의 경계.

## 변경 정책

이 문서는 **3개 트리거** 시 갱신한다.

1. **분기 GTM 리뷰**: 위 "분기별 리스크 핫리스트" 점검 + 현 분기 KR 달성률 평가 + 다음 분기 KR 미세 조정. 분기 OKR 숫자는 v1 가설이므로, 매 분기 리뷰에서 데이터 기반 조정 가능.
2. **Phase 종료**: 각 Phase 종료 시점에 다음 Phase의 분기 OKR / 진입 조건 / 종료 조건을 재정의. Phase 종료 조건 미충족 시 다음 Phase 진입 보류 + Watch List 발동 점검.
3. **Watch List 신호 발견**: [`product-vision.md`](../00-vision/product-vision.md) Watch List 6개 중 1개 이상 발견 시 분기 기다리지 않음. Phase 마이그레이션 결정 시점도 앞당김.

**금지 사항**

- 영업 압력만으로 분기 KR 끼워넣기 — 거절. KR은 Phase 종료 조건의 분기 분해여야 함.
- 분기 OKR을 절대 숫자로 박기 — draft v1 가설이므로 "방향 + 임계치"로 읽고 매 분기 조정.
- 한 분기에 2개 이상 Objective 박기 — 1 분기 = 1 Objective 원칙. 자원 분산 방지.
- 다음 Phase의 빌드 항목을 현 Phase에 끼워넣기 — Phase 간 평행 진행 금지 ([`product-vision.md`](../00-vision/product-vision.md) 원칙).

**책임자**: Product Lead (1차) + Engineering Lead (분기 KR 실행 가능성 검증) + Sales Lead (Phase 3+ ACV·견적 KR 검증). 갱신 시 변경 이력을 본 파일 하단에 추가.
