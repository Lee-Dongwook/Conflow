## 1. JTBD 핵심 원칙

> 고객은 제품을 사는 게 아니라, 자신의 Job을 처리하기 위해 **고용(hire)**한다.
> Job = **상황(When) + 동기(I want to) + 기대 결과(So I can)**

Conflow의 Job은 **"태스크 관리"가 아니다.** 그건 결과 기능이지 Job이 아니다.
진짜 Job은 — **"불안을 정리해서, 관계를 다치지 않고, 책임을 분산시키는 것"**이다.

## 2. Conflow의 핵심 Job Statements

### Job 1 — 불안한 리더의 책임 분산 (★ Phase 1 본진)

> **When** 팀플 마감이 3주 안에 다가오고 팀원들이 카톡에 답을 안 할 때,
> **I want to** 누가 어디서 막혀 있는지, 누가 무엇을 해야 하는지를 한 화면에서 직시하고,
> **So I can** "혼자 다 떠안을지도 모른다"는 불안에서 벗어나고, 갈등 없이 책임을 가시화할 수 있다.

- **결제 트리거:** 불안의 임계점 (마감 D-14 즈음)
- **현재 고용 중인 대체재:** Notion + 카톡 + GitHub Projects + 본인 스트레스
- **해고 트리거(이탈 사유):** "결국 내가 다 하게 됨" — 도구가 책임 분산을 만들지 못하면 즉시 해고

### Job 2 — 운영자의 멤버 이탈 방어

> **When** 스터디 6주차에 발표 펑크가 반복되고 멤버들이 단톡방에서 조용해질 때,
> **I want to** 매주 작은 약속(이번 주 목표)을 시각적으로 묶어두고 자동 리마인드해서,
> **So I can** 멤버가 "여기 안 나와도 표 안 남" 느끼지 않게 하고, 운영자인 내가 잔소리꾼이 되지 않을 수 있다.

- **결제 트리거:** 멤버 1명이 첫 잠수 탔을 때
- **대체재:** Discord 봇 + 구글 폼 출석체크
- **해고 트리거:** UX 마찰이 크면 멤버 이탈 가속 → 운영자가 도구 자체를 버림

### Job 3 — 신입 연구자의 진행 보고

> **When** 교수님과 주간 미팅 24시간 전이 됐을 때,
> **I want to** 이번 주 진행/막힘/다음 액션을 5분 안에 요약 가능한 형태로 갖춰두고,
> **So I can** "뭐 했냐"는 질문에 즉답할 수 있고, 막힘을 숨기지 않고 도움을 요청할 수 있다.

- **결제 트리거:** 미팅 직전의 공포
- **대체재:** Notion + Slack + 본인 노트
- **해고 트리거:** 교수/선배가 다른 툴을 강제할 때

### Job 4 — (확장 시드) 사회 초년생의 사이드/공동 작업

> **When** 졸업 후 첫 회사·사이드 프로젝트·창업 동아리에서 3~5명 단위 협업을 시작할 때,
> **I want to** 학생 때 쓰던 친숙한 "이번 주 목표 + 막힘" 구조를 그대로 유지하면서 회사 메신저(Slack/카톡 워크)와도 연결하고,
> **So I can** 새 툴 학습 비용 없이, 같이 일하는 사람들과 책임 가시화를 이어갈 수 있다.

- **결제 트리거:** 학생 시절 사용 습관 + 새 팀 도입 결정권
- **대체재:** Jira/Linear/Notion (학습 비용 큼)
- **해고 트리거:** "회사용으론 너무 가벼움" — 별도 Pro 라인 필요
- **위치:** 본 단계 Out of Scope. **페르소나 확장 단계에서 본격 정의.**

## 3. Job Map — "고용 → 해고"까지의 흐름

각 Job이 어떻게 시작·심화·이탈로 이어지는지 한 줄로 정리.

| 단계      | Job 1 (캡스톤 리더)                            |
| --------- | ---------------------------------------------- |
| Awareness | 단톡방에 답이 안 옴, 마감은 다가옴             |
| Hire      | "팀원 초대 → 이번 주 목표 등록" 5분 안에 완료  |
| Aha       | 등록한 막힘에 24h 내 누군가 반응함             |
| Habit     | 매주 일요일 밤 자동 알림 → 이번 주 목표 점검   |
| Fire      | "결국 나만 등록함" — 가시화가 행동을 못 일으킴 |

→ **Fire 방어선**이 곧 본 제품의 생존선. 그래서 **알림·멘션·에스컬레이션**이 Blocker UI보다 중요.

## 4. User Story (Phase 1 — Job 1 중심)

각 스토리는 INVEST 원칙(Independent, Negotiable, Valuable, Estimable, Small, Testable)에 따라 작성.
**Acceptance Criteria**까지 1줄 명시.

### US-1. 팀 생성 + 카톡 공유 초대 (Must)

> **As** 캡스톤 팀장으로서,
> **I want to** 30초 안에 팀을 만들고 카톡으로 초대 링크를 보내고 싶다,
> **Because** 팀원들이 단톡방에서 즉시 들어와야 도구가 시작되기 때문이다.

- **AC:** 팀명 + 이메일만으로 생성 / 초대 링크가 카톡 공유 OG 카드로 변환 / 게스트 1회 미가입 진입 허용

### US-2. 이번 주 목표 3개 등록 (Must)

> **As** 팀장으로서,
> **I want to** 매주 일요일 밤에 "이번 주 우리 팀이 해낼 것 3개"를 등록하고 싶다,
> **Because** 스프린트라는 단어를 쓰지 않고도 팀의 한 주를 묶고 싶기 때문이다.

- **AC:** 목표당 담당자 1명 필수 지정 / 마감일 자동 = 다음 일요일 / 등록 즉시 팀원에게 카톡/푸시 알림

### US-3. 도움 요청 (구 Blocker) 카드 (Should)

> **As** 막힌 팀원으로서,
> **I want to** "막혔다" 대신 "도움 요청"이라는 표현으로 상황을 등록하고 싶다,
> **Because** "내가 못한다"는 공개 선언은 부담스럽지만 "같이 풀어보자"는 부담이 적기 때문이다.

- **AC:** 카드 생성 시 "어떤 도움이 필요한지" 1줄 필수 / 등록 즉시 멘션 1명 강제 / 24h 무응답 시 팀 전체 자동 알림

### US-4. D-Day 카운트다운 대시보드 (Must)

> **As** 팀장으로서,
> **I want to** 대시보드 상단에서 가장 임박한 마감 1개를 D-Day 형태로 보고 싶다,
> **Because** 카톡 단톡방에서 "그거 언제까지였지?"라는 질문이 더 이상 안 나와야 하기 때문이다.

- **AC:** 로그인 후 첫 화면 상단 고정 / 7일 이내면 빨강 강조 / 대시보드 진입 시 자동 갱신

### US-5. 학기말 팀플 리포트 PDF (Should)

> **As** 졸업프로젝트 팀원으로서,
> **I want to** 학기말에 팀별 기여도/마감 완수율/막힘 해결 시간 등을 PDF로 받고 싶다,
> **Because** 교수님께 산출물 외에 "어떻게 협업했는지"를 증빙할 수 있으면 평가에 유리하기 때문이다.

- **AC:** 학기 종료 시 자동 생성 알림 / 1클릭 다운로드 / 카톡 공유 가능 / 익명화 옵션 선택 가능

### US-6. 자동 회의록 → 액션아이템 드래프트 (Could — Phase 2)

> **As** 회의 직후의 팀장으로서,
> **I want to** 회의록을 붙여넣으면 "이번 주 목표" 드래프트로 자동 변환되길 원한다,
> **Because** 회의 끝나고 30분 내에 결정사항이 휘발되기 때문이다.

- **AC:** 입력은 텍스트 붙여넣기로 충분 / 액션아이템마다 담당자 추측 + 사용자가 확정/수정 / **AI가 자동 할당하지 않음**

### US-7. 카톡 알림톡 발송 (Should)

> **As** 팀원으로서,
> **I want to** Conflow에서 발생한 멘션/마감 임박을 카톡으로 받고 싶다,
> **Because** 나는 Conflow 앱을 매일 안 들어가기 때문이다.

- **AC:** 알림톡 발송 / 1-tap으로 해당 카드 딥링크 진입 / 알림 빈도 사용자 제어 (스팸 방지)

## 5. 빠진 Job (의도적으로 제외)

- "팀원 평가/순위 매기기" — Job 1과 충돌(갈등 유발). 절대 만들지 않음
- "스프린트 회고 자동화" — 대학생 어휘에 없는 용어. Won't
- "간트 차트" — Job 1~3에 해당 Job 없음. Phase 2+ Won't

## 6. 다음 단계 (페르소나 확장과의 연결고리)

본 문서는 **학생(Phase 1)** 중심으로 작성되었으나, **Job 4(사회 초년생)** 의 존재를 명시했다.
페르소나 확장 단계에서:

- Job 4를 정식 Job으로 승격할지 (= Conflow Work 라인 분기 시점)
- 또는 학생 → 사회 초년생 전환 시 **Job 1의 변형**으로 처리할지 (= 단일 제품 유지)

결정 필요. 이것이 본 프로젝트의 **장기 수익 구조**를 가르는 분기점이다.
