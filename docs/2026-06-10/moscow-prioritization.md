# Conflow MoSCoW 우선순위 재정렬

> 작성일: 2026-06-10
> 목적: 현재 로드맵 + 빠진 인프라 + 신규 발굴 항목을 Must/Should/Could/Won't로 강제 분류
> 기준: **Phase 1 (다음 90일)** — 90일 후 재평가

---

## 분류 원칙

- **Must (M):** 없으면 제품이 아님 / 핵심 가설 검증 자체가 불가
- **Should (S):** 있으면 가치 ↑↑, 없어도 제품은 동작 (그러나 90일 내 출시 권장)
- **Could (C):** 있으면 좋음, 자원 남으면 / 또는 90일 후 재평가
- **Won't (W):** 본 Phase 범위 밖. 만들지 않음 (단순 "보류"가 아닌 **명시적 제외**)

## ⚫ Won't — Phase 1에서 명시적 제외

| # | 항목 | 제외 이유 |
|---|---|---|
| W1 | **LangGraph 자동 태스크 할당 엔진** | 사용자 신뢰 미검증. 만들면 기술 부채 |
| W2 | **Python 샌드박스 / Landlock 보안 레이어** | LangGraph가 Won't인 한 불필요 |

| W5 | **모노레포 패키지 세분화** | apps/web + packages/shared 2개로 시작 |

## 우선순위 검증 — 90일 분량 점검

- Must 9개 = 약 5~6주 (1인 풀타임)
- Should 7개 중 핵심 4개(S1, S3, S4, S7) 추가 = 약 3~4주
- **합산 8~10주** → 90일(13주) 내 Must + 핵심 Should 가능
- 남은 3~5주: 실험 운영(인터뷰, Fake Door, Wizard of Oz), 디자인 반복, 사용자 피드백 반영

→ **현실적인 범위.** 단, **Won't 항목에 손대지 않는 규율**이 본 분류의 절반.

---

## 분기 트리거 — Must로 승격될 가능성이 있는 Could 항목

다음 신호 발생 시 **즉시 재분류 검토**:

| 신호 | 승격 후보 |
|---|---|
| 실험 B (교수 인터뷰)에서 3+ 명이 파일럿 의향 | C3 (교수 대시보드) → M |
| 실험 A에서 자발적 Blocker 등록률 < 20% | C2 (자동 감지) → M, S1 강등 |
| 카톡 공유로 들어온 신규 유저 < 10% | M6 재설계, S2 (알림톡) 가속 |
| 학기말 PDF 사용률 > 50% | S3 → 다음 Phase의 핵심 retention 무기 |
