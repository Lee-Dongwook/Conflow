# Conflow 페르소나 확장 — 신입/주니어 직장인 (Conflow Work)

> 작성일: 2026-06-10
> 결정: **신입/주니어 직장인 (졸업 0~3년차) 확장**, **PMF 도달 후 라인 분기 (Student / Work)**
> 참조: [[jtbd-user-story]] Job 4 / [[pmf-playbook]] §8 / [[market-researcher]] §4 / [[moscow-prioritization]] W11

---

## 1. 확장 의사결정 — 한 줄 정리

> **Phase 1은 학생 PMF에 100% 집중.** PMF 도달 시점에 **데이터는 마이그레이션하되 제품은 라인 분기**한다.
> 이유: 학생용 단순성("이번 주 목표 3개")과 직장인용 표현력(권한·조직·통합)은 단일 UI로 절대 양립 불가.

핵심 베팅: **학생 → 신입 직장인 전환은 자연 트래픽**이지, 마케팅 비용이 아니다.
→ Conflow의 진짜 해자는 "졸업 시점에 이미 익숙해진 협업 도구"라는 위치다.

## 2. 신입/주니어 직장인 페르소나 (정식 정의)

### 페르소나 D — "신입 PM 지원" (Conflow Work 본진)

- **나이/직급:** 25~28세, 입사 1~3년차 / PM 어시스턴트, 주니어 디자이너, 주니어 개발자
- **회사 규모:** 시드~Series A 스타트업 (10~50명), 또는 대기업 3~5인 셀
- **현재 협업 환경:** Slack/Teams + Notion/Confluence + Jira/Linear/Asana 1개 + 카카오워크/카톡
- **고통:**
  1. 회의가 끝나면 액션아이템이 휘발됨 (회의록 작성 책임 떠넘기기)
  2. "내가 뭘 해야 하는지"가 항상 불명확 — Jira 티켓 본인이 만들 권한 없거나 만들기 부담
  3. 시니어/PM에게 "어디까지 했냐"는 질문에 즉답할 준비가 없음
  4. 사이드프로젝트/스터디까지 Notion + Jira로 관리하기엔 무거움
- **트리거:** 입사 후 첫 1on1 / 첫 분기말 회고 / 처음으로 본인이 작은 프로젝트 리드 맡았을 때
- **구매 결정자:** 본인 (개인 결제) → 또는 팀장 (3~10인 팀 결제) — **개인 → 팀**의 자연 확장

### 페르소나 E — "사이드프로젝트 리더"

- **나이/직급:** 26~32세, 본업 + 사이드 (소규모 스타트업 준비, 부업 팀, 학생창업 졸업팀)
- **고통:** 본업용 Linear는 너무 무겁고, 노션은 안 들어옴, 카톡은 휘발
- **트리거:** 사이드 팀이 3인 넘어가는 순간
- **결정자:** 본인 — 개인 결제 의지 높음 (월 1~2만원 OK)

### 페르소나 D · E 공통점
- **학생 시절 Conflow를 썼던 경험**이 진입 장벽 0의 결정적 이점
- **"가벼움 + 책임 가시화"** 가치 제안은 그대로 유효
- **새로운 가치:** 회사 도구(Slack, Linear, Jira)와의 통합

## 3. Job 4 정식 승격 — Conflow Work의 Job

> **When** 회사·사이드 팀에서 3~5명 단위 협업이 시작되고 기존 회사 도구가 무겁거나 부재할 때,
> **I want to** 학생 때 익숙한 "이번 주 목표 + 도움 요청" 구조를 그대로 쓰면서 회사 메신저·이슈 트래커와 연결하고,
> **So I can** 새 툴 학습 비용 없이 시니어에게 진행상황을 5분 안에 보고하고, 본인이 막힌 부분을 자연스럽게 가시화할 수 있다.

**결제 트리거 (학생 Job 1과의 차이):**
- 학생: 불안 임계점 (마감 D-14) → **무료 가입**
- 직장인: 첫 분기 회고 / 첫 1on1 / 사이드 팀 3인 돌파 → **개인 결제 / 팀 결제**

## 4. Conflow Student vs Conflow Work — 라인 분기 매트릭스

| 항목 | Conflow Student | Conflow Work |
|---|---|---|
| **타깃** | 대학생 팀플/스터디 | 신입~주니어 직장인 + 사이드팀 |
| **핵심 가치** | 책임 가시화 + 마감 망각 방지 | 책임 가시화 + 시니어 보고 + 도구 통합 |
| **UI 복잡도** | 매우 낮음 (이번 주 목표 3개) | 중간 (목표 5~10개, 우선순위, 태그) |
| **권한 모델** | 평등 (모든 팀원 동일 권한) | 역할 구분 (Owner / Editor / Viewer) |
| **통합** | 카톡 OG 공유 + 알림톡 | Slack, Linear, Jira, Notion 양방향 + 카카오워크 |
| **AI 기능** | 회의록 → 액션아이템 드래프트 (수동 수락) | 동일 + Slack 채널 자동 요약, 1on1 준비 자동 생성 |
| **모바일** | PWA 중심 | PWA + 데스크톱 앱 (Slack 옆에 항상 떠있음) |
| **알림** | 카톡 알림톡, 푸시 | Slack DM, 이메일, 카카오워크 |
| **수익 모델** | Freemium (5인 이하 무료) + 학과 라이선스 | 개인 4,900원 / Pro 팀 9,900원/인 / Enterprise |
| **마케팅** | 에브리타임, 인스타 릴스, 학회 | Wanted, 링크드인, 시니어 PM 추천 |
| **데이터** | 익명 학기말 PDF 리포트 | 분기별 OKR 리포트, 시니어 공유용 |
| **브랜드 톤** | "팀플 빌런 없는 한 주" | "월요일 아침이 두렵지 않은 한 주" |

→ **두 라인은 같은 코어(이번 주 목표 + 도움 요청)를 공유하되, UI/통합/권한이 완전히 분기.**

## 5. 데이터 마이그레이션 모델 — "졸업 마이그레이션"

졸업 시점에 학생 사용자에게 제공할 단일 화면:

### Migration Flow
1. **학생 사용자가 졸업 학기말에 "Conflow Work로 졸업하기" 알림 수신** (자동 트리거)
2. **3가지 옵션 제시:**
   - (a) Student 그대로 유지 (대학원/추가 학기)
   - (b) **Work으로 이주 (개인 무료 → 14일 트라이얼)** ← 권장 경로
   - (c) 데이터 PDF 백업만 받고 종료
3. **이주 선택 시:** 기존 팀 데이터는 읽기 전용 아카이브, 새 워크스페이스 자동 생성
4. **3개월 내 1회 본인이 결제하지 않으면 자동 무료 계정 (Slack 알림 1개/주 제한)**

### Migration의 진짜 가치
- **학생 시절 동료 4~5명이 같이 졸업** → 한 명이 Work으로 이주하면 **나머지에게도 자동 초대 발송**
- → **K-factor 1.5~2.0 가능** (학생 시절 팀 = 졸업 후 사이드/창업/추천 네트워크)
- → 이게 **"4년 LTV가 아닌 평생 LTV"**의 본진

## 6. 수익 모델 변화 — 학생 단계는 적자 마케팅, 직장인 단계가 본진

### Conflow Student (학생)
- 거의 모든 기능 무료
- 학과 라이선스 (학생당 연 5,000~10,000원) ← 학교 영업 가능 시
- **목표: Break-even이 아닌 PMF + 졸업 전환율 30%+**

### Conflow Work (직장인)
| 플랜 | 가격 | 타깃 |
|---|---|---|
| Free | 무료 (5인/1팀) | 사이드 팀, 초기 사용 |
| Personal | 4,900원/월 | 사이드프로젝트 리더, 1인 사용자 |
| Pro Team | 9,900원/인/월 | 스타트업 셀, 3~20인 |
| Business | 19,900원/인/월 | 50인+, SSO, 감사로그, SLA |

### LTV 계산 (추정)

- **학생 단계:** 평균 3년 × 무료 → 직접 매출 0원
- **졸업 후 전환:** 30% 가정 × Personal 4,900원/월 × 평균 18개월 → **약 88,000원/인**
- **팀 전환:** Personal 사용자 중 20%가 팀 결제로 승격 × 평균 5인 × 9,900원/월 × 12개월 → **약 594,000원/팀**
- **결과:** 학생 1인의 **장기 LTV는 약 12~17만원**으로 추정 (Pure 학생 ARPU 0원 대비 무한대)

CAC가 학생 단계에서 0에 수렴하므로 (바이럴 루프), **LTV/CAC는 12~17만원 / 거의 0** — 이게 모델의 핵심.

## 7. PMF 도달 시점에 라인 분기를 트리거하는 조건

[[pmf-playbook]] §8과 정합. 다음 조건 **모두 충족 시 Work 라인 빌드 시작**:

| 조건 | 정량 기준 |
|---|---|
| Student PMF 도달 | Sean Ellis "매우 실망" ≥ 25% |
| 활성 학생 팀 | 100팀+ |
| 졸업 예정 사용자 | 50명+ (Work 잠재 시드) |
| 마이그레이션 의향 인터뷰 | 졸업 예정자 10명 중 5+명이 "졸업해도 쓰고 싶다" 발화 |
| 자원 | 공동창업자 1명 또는 첫 외부 자금 |

→ **조건 미충족 시 Work 라인은 빌드하지 않는다.** Student를 더 깊게 판다.
→ **5개 중 4개 충족까진 "사이드 실험"**, 5개 모두 충족 시 정식 라인 분기.

### 7-A. 별도 트랙 — 창업 동아리 운영진 비치헤드 (icp-expand-strategy 반영)

위 §7 표는 **Work 라인(직장인 페르소나) 빌드** 트리거다. [[icp-expand-strategy]] §5.5의 "창업 동아리 운영진 결제 비치헤드"는 **별도 트랙**으로, PMF 전 단계에서 병행 검증이 가능하다.

| 트랙 | 페르소나 | PMF 전 가능 행위 | PMF 후 빌드 |
| --- | --- | --- | --- |
| Track A (본 §7) | 신입/주니어 직장인 (Job 4) | 시그널 관찰만 | Work 라인 신규 빌드 |
| Track B ([[icp-expand-strategy]] §5.5) | 창업 동아리 운영진 | 90일 검증 가능. 통과 시 운영진 대시보드 Must 승격 | Student 라인 내 레이어 추가 (Work 분기 아님) |

핵심: Track B 통과 ≠ Conflow Work 빌드. 운영진은 학생 페르소나 A의 **상위 결제 단위**이지 직장인 페르소나가 아니다.

## 9. 확장 리스크 — 무엇이 이 전략을 깨뜨리는가

| 리스크 | 완화 |
|---|---|
| **학생 → 직장인 전환율이 < 10%** | 졸업 마이그레이션 UX 강화, 학생 시절 친구를 함께 끌어오는 인센티브 |
| **직장인이 "학생 도구" 인식 거부** | Conflow Work 브랜드/UI 완전 분리, "학생 출신"임을 마케팅에 노출하지 않음 |
| **Slack/Linear/Jira와의 경쟁 정면 충돌** | "Linear의 대체"가 아닌 **"Linear 옆에 살아남는 가벼운 보고용 레이어"** 포지셔닝 |
| **Student 라인이 PMF 도달 못 함** | Work 라인 빌드 자체를 보류. Student PMF가 전제 조건 |
| **두 라인 동시 운영 인지 부담** | 분기 시점에 공동창업자 합류 또는 외부 자금 조건. 1인 운영 시 절대 분기 안 함 |

## 10. 본 결정의 한 줄

> Conflow는 **"학생 시절 마음을 잡은 후 그 사람과 평생 일하는"** 협업 도구다.
> Student는 PMF의 학교, Work는 LTV의 본진이다.
> 두 라인을 섞지 말고, **데이터(친구·습관·이력)만 잇는다**.
