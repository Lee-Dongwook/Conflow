# Conflow PMF 검증 플레이북

> 작성일: 2026-06-10
> 목적: 90일 실험을 **PMF(Product-Market Fit) 가설 검증** 프레임에 재구성
> 전제: 현 단계는 **Pre-PMF**. 모든 행위는 PMF 가설 검증을 위한 수단

---

## 1. PMF란 무엇이며, 무엇이 아닌가

**PMF =** "이 제품 없으면 매우 실망할 것"이라고 답하는 사용자가 **40% 이상** 도달한 상태
(Sean Ellis test)

PMF가 **아닌 것**:
- 가입자 수가 많음 — Vanity Metric
- 첫 사용자가 좋아함 — N=1 함정
- 투자자가 좋다고 함 — 그들은 사용자가 아님
- 본인이 만족함 — 가장 위험한 함정

PMF의 4대 시그널 (PMF가 가까울 때 나타나는 행동):
1. **자발적 입소문** — 마케팅 없이 신규 가입이 발생
2. **이탈 저항** — 서비스 장애 시 항의 메시지가 옴
3. **사용 빈도 증가** — 같은 코호트의 주차별 활성률이 우상향
4. **돈을 내려 함** — 결제 페이지가 없는데 "어디서 결제하냐"는 문의

→ **이 4개 중 0개라면 PMF 검증을 시작할 자격조차 없다는 신호.** 가설부터 다시.

## 2. Conflow의 PMF 핵심 가설 (3개)

### 가설 H1 — Problem-Solution Fit (가장 먼저 검증)

> **"한국 대학생 캡스톤 팀장은 '책임 분산을 위한 가시화 도구'에 대한 의식적 수요가 있다."**

- **검증 방법:** 인터뷰 + Fake Door 실험 (실험 A, C — business-analyst.md 참조)
- **PMF 신호:** 인터뷰 5명 중 4명+이 "이거 학기 시작 전에 알았으면 썼다" 자발 발화
- **반증 시 행동:** ICP 재정의 또는 Pivot (코딩 스터디 운영자 / 대학원 신입으로 ICP 이동)

### 가설 H2 — Behavior-Habit Fit

> **"팀이 한 번 들어오면 학기 13주 중 8주 이상 매주 1회 이상 액션을 일으킨다."**

- **검증 방법:** Wizard of Oz 1주(실험 D) → 실제 빌드 후 8주 코호트 추적
- **PMF 신호:** D7 리텐션(팀 단위) 40%+, W4 리텐션 25%+
- **반증 시 행동:** 알림/리마인드 구조 강화 (S4, S7) → 그래도 안 되면 본 가치제안 자체를 의심

### 가설 H3 — Willingness-to-Pay (가장 어려움)

> **"학생은 본인이 직접 결제하지 않더라도, 학과/학회/교수를 통해 학기당 학생 1인 5,000~10,000원의 가치를 발생시킨다."**

- **검증 방법:** 교수 인터뷰 5명(실험 B) + 학과 파일럿 MOU 1건
- **PMF 신호:** 학과 1곳 이상 "다음 학기 캡스톤에 도입 검토" 의향
- **반증 시 행동:** B2B2C 폐기, Freemium만 유지하되 LTV는 졸업 후 B2B 전환에 의존

## 3. Sean Ellis Test 적용 설계

### 측정 시점

- **첫 측정:** 베타 사용자 50명 도달 시 (M9~M1 출시 완료 + 6~8주차)
- **재측정:** 12주차, 학기 종료 시점

### 질문 (단 1개)

> "오늘부터 Conflow를 더 이상 쓸 수 없게 된다면 당신은 어떻게 느낄까요?"
>
> 1. 매우 실망할 것이다 (Very disappointed)
> 2. 약간 실망할 것이다 (Somewhat disappointed)
> 3. 실망하지 않을 것이다 (Not disappointed)
> 4. 이미 안 쓴다 (N/A)

### 판정 기준

| "매우 실망" 비율 | 해석 | 다음 행동 |
|---|---|---|
| **≥ 40%** | PMF 도달 | Growth로 전환 (CAC/LTV 최적화) |
| 25~39% | PMF 임박 | "매우 실망" 코호트만 분리해 그 행동을 모방하도록 제품 조정 |
| 10~24% | Pre-PMF | 가치제안 또는 ICP 재검토 |
| < 10% | 가설 실패 | Pivot 결정 |

### 보조 질문 2개 (필수)

1. "이 제품의 주요 가치는 무엇이라고 생각하나요?" — 우리가 의도한 가치와 사용자가 인지한 가치 일치 여부 측정
2. "친구에게 추천한다면 누구에게 추천할까요?" — 진짜 ICP 발견 (우리가 정의한 ICP와 다를 수 있음)

## 4. PMF 까지의 단계 정의

PMF 도달 전 4단계 (Pre-PMF → PMF Path):

| 단계 | 정의 | 측정 기준 | 본 단계 진입 신호 |
|---|---|---|---|
| **Stage 0 — Hypothesis** | 가설만 있음 | 인터뷰 0명 | (현재 위치) |
| **Stage 1 — Problem Validation** | 페인 존재 확인 | 인터뷰 10명+, "이건 진짜 문제다" 발화 70%+ | 가설 H1 검증 시작 |
| **Stage 2 — Solution Validation** | 솔루션 수용 확인 | Wizard of Oz 1주, 주 3회+ 사용 의향 70%+ | 실험 D 통과 |
| **Stage 3 — Pre-PMF Build** | MVP 출시, 행동 데이터 수집 | 활성 팀 20+, W4 리텐션 15%+ | Must 9개 출시 완료 |
| **Stage 4 — PMF Test** | Sean Ellis 측정 | "매우 실망" ≥ 40% | 베타 사용자 50명+ |
| **Stage 5 — PMF Achieved** | 확정 | 자발 입소문 + 결제 문의 | Growth Phase 진입 |

→ **현재 → Stage 1로 가는 게 90일의 1차 목표.** Stage 3 도달은 욕심.

## 5. 90일 실험을 PMF 프레임에 매핑

business-analyst.md의 실험 A~D + 추가 실험을 단계별로 정리.

### Week 1~2: Stage 0 → Stage 1 (Problem Validation)

- **실험 A** — 스터디 팀 3개 인터뷰 (15명, Blocker 등록 의향)
- **실험 B** — 교수 5명 인터뷰 (B2B2C 의향)
- **추가:** "캡스톤 리더" 페르소나 5명 1:1 인터뷰 (JTBD 정확도 검증)
- **PMF 게이트:** 인터뷰 평균 페인 강도 7/10+ → 다음 단계
- **실패 시:** ICP 재정의 또는 Pivot

### Week 3~4: Stage 1 → Stage 2 (Solution Validation)

- **실험 C** — Fake Door 랜딩 (에브리타임 + 학과 오픈채팅 3곳)
- **실험 D** — Wizard of Oz 1주 (실제 팀 2개, 카카오 오픈챗 + 시트로 수동 운영)
- **PMF 게이트:** Fake Door 전환율 15%+, Wizard of Oz 주 3회+ 사용 의향 70%+
- **실패 시:** 가치제안 또는 핵심 기능 재설계

### Week 5~10: Stage 2 → Stage 3 (Pre-PMF Build)

- M1~M9 (Must 9개) 출시
- 베타 30~50팀 유치 (캡스톤 학과 1~2곳 집중)
- **측정:** D7/W4 팀 리텐션, "이번 주 목표" 등록률, "도움 요청" 등록률
- **PMF 게이트:** W4 팀 리텐션 25%+, 활성 팀 20+

### Week 11~13: Stage 3 → Stage 4 (PMF Test)

- Sean Ellis test 50명 시행
- 보조 질문으로 ICP/가치 인식 검증
- **PMF 게이트:** "매우 실망" 25%+ (40%는 아직 욕심)
- **실패 시:** 25% 미만의 사용자 인터뷰 → 다음 분기 재설계

## 6. PMF 검증 안티패턴 (피해야 할 함정)

- **"베타 사용자가 좋다고 했어요"** — 친구/지인은 사용자가 아님. **콜드 가입자**만 측정 대상
- **"가입자가 늘고 있어요"** — 가입 ≠ 사용. **재방문 코호트**가 진실
- **"기능 더 추가하면 좋아할 거예요"** — Pre-PMF에서 기능 추가는 거의 항상 산만함을 늘림
- **"좀 더 기다려보면 돼요"** — 데이터가 평평한데 시간을 기다리는 건 가설 실패의 인정 회피
- **"우리 제품은 카테고리가 달라서 PMF 기준이 안 맞아요"** — 거의 모든 경우 변명. Sean Ellis test는 SaaS 전반에 작동

## 7. PMF 도달 시 신호 vs 미도달 시 신호 (조기 경보)

### 도달 시그널 (6주차 안에 1개라도 보이면 PMF 가능성)

- 베타 사용자가 친구를 자발적으로 데려옴 (K > 0.3)
- "왜 안 되는데?" 류 항의 메시지 등장 (이탈 저항)
- 카톡 공유 OG 카드의 자연 확산 (M6 추적)
- 결제 페이지 없는데 결제 문의 1건+

### 미도달 시그널 (6주차 안에 1개라도 보이면 Pivot 검토)

- 활성 팀이 50% 이상 D14에 사라짐
- "이번 주 목표" 등록은 되는데 다음 주 재등록률 < 20%
- "도움 요청" 등록률 < 10%
- 인터뷰에서 "왜 안 쓰냐"는 질문에 "그냥 까먹어요" 답변 다수

## 8. PMF 이후 — 다음 단계 미리보기

PMF 도달 시 즉시 전환할 작업:

1. **Growth metrics 정의** — CAC, LTV, K-factor, Payback period
2. **수익 모델 활성화** — Freemium → Pro 또는 학과 라이선스 영업
3. **두 번째 페르소나 확장** — 두 트랙 중 선택:
   - **Track A**: 사회 초년생/직장인 (Job 4) → [[persona-expansion]] §7. Conflow Work 라인 신규 빌드
   - **Track B**: 창업 동아리 운영진 → [[icp-expand-strategy]] §5.5. Student 라인 내 운영진 레이어 추가 (Work 분기 아님)
   - **선택 기준**: Phase 0 듀얼 검증 결과 + LTV 시뮬레이션. 단, 자원 한계상 두 트랙 동시 진입은 불가
   → **이 시점이 "페르소나 범주 확장" 의사결정의 자연스러운 분기점**

### 8-A. Phase 0(PMF 전) 단계의 듀얼 검증 — 사전 안내

본 §8은 "PMF 후" 시점을 다루지만, [[icp-expand-strategy]] §5.5는 **PMF 전** 단계에서 운영진 트랙의 결제 의사·페인 강도를 병행 검증하는 것을 허용한다. 이는 §2의 H1~H3 가설 검증과 충돌하지 않으며, Track B 시그널이 H1~H3보다 먼저/강하게 나오면 Stage 3 빌드 우선순위가 운영진 대시보드로 전환된다.
